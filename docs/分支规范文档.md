# 分支规范文档

## 目的

- 统一团队分支命名，降低协作与发布风险。
- 通过本地钩子自动校验分支名，避免不合规分支进入远端。

## 允许的分支命名规则

- 主干分支：`main`、`master`、`develop`
- 发布分支：`release/<name>`
- 功能与维护分支：`feature/<name>`、`fix/<name>`、`hotfix/<name>`、`chore/<name>`、`refactor/<name>`、`docs/<name>`、`test/<name>`

## `<name>` 命名约束

- 只允许小写字母、数字、点号、下划线、短横线：`[a-z0-9._-]+`
- 不允许空格与中文。

## 合法示例

- `feature/user-list-page`
- `fix/login-token-expired`
- `hotfix/prod-403`
- `chore/update-eslint-config`
- `release/2026.03.29`

## 非法示例

- `Feature/UserList`
- `feature/用户管理`
- `bugfix/login-error`
- `feature/user list`

## 校验机制

- 分支名校验脚本：`scripts/validate-branch-name.mjs`
- 本地触发时机：`.husky/pre-push`
- 手动执行：`pnpm check:branch-name`

## 失败提示

- 当分支名不符合规范时，推送会被阻断，并输出允许格式说明。
