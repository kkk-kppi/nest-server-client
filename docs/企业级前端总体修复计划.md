# 企业级前端总体修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除当前项目在发布、安全、权限、HTTP、表格表单、可观测性和质量门禁方面的高风险缺陷，将项目提升为可复制、可验证、可持续演进的企业级前端启动模板。

**Architecture:** 整改遵循“发布链路先于业务能力、运行时正确性先于体验增强、单一事实源先于功能扩展”的顺序。总体拆分为四个可独立交付的工作流：P0 发布与安全、P1 核心运行时、P2 业务黄金路径、P3 工程治理；每个工作流都必须通过测试驱动方式交付，并以可执行门禁而不是文档声明作为验收依据。

**Tech Stack:** Vue 3、TypeScript、Vite 8、Vue Router、Pinia、Axios、Naive UI、Vitest、Vue Test Utils、Playwright、MSW、Storybook、Docker、Nginx、GitHub Actions、Sentry。

---

## 1. 背景与目标

当前项目已经具备 `app/core/features/shared` 分层、HTTP 封装、动态路由、RBAC、MSW、Vitest、Playwright、Storybook、CI/CD、Docker 和可观测性等基础设施，但评审确认存在以下结构性问题：

- 非生产流水线仍可能按 production mode 构建，环境配置与发布目标不一致。
- Docker 静态产物没有有效运行时配置机制，API 地址可能回退到浏览器 `localhost`。
- Nginx CSP 与当前跨域 API、Sentry 配置冲突。
- 构建、扫描和部署不是同一个不可变发布物。
- 路由权限采用 fail-open，动态路由只添加不卸载。
- HTTP token 注入、去重、取消、重试和 401 处理存在安全问题或竞态。
- API endpoint 没有结构化区分 path/query/body，响应缺少运行时验证。
- ProTable、ProForm 和 CRUD 示例没有形成可复制的业务闭环。
- 关键错误被降级为空数据、404、旧数据或“系统正常”。
- 覆盖率、E2E、Stylelint、Prettier 和依赖审计门禁没有在 CI 中真实闭环。

本计划不以继续增加通用组件数量为首要目标。第一目标是让已有能力安全、正确、可测试；第二目标是提供一条完整的业务开发黄金路径。

## 2. 实施原则

1. 每个缺陷先写能复现真实行为的失败测试，再修改实现。
2. P0 未完成前，不新增大规模业务功能或组件。
3. 不通过缩小 coverage 范围维持漂亮指标。
4. 不使用 `any`、`as unknown as`、`@ts-ignore` 绕过新类型问题。
5. 不新增兼容旧错误行为的分支，除非有已发布数据或外部消费者要求。
6. 前端权限只控制交互体验，后端 API 必须独立完成授权。
7. 构建、扫描、部署和回滚必须围绕同一不可变 artifact 或 image digest。
8. 每个阶段完成后运行对应专项测试和完整质量门禁。

## 3. 目标架构与文件职责

### 3.1 配置与发布

- `public/runtime-config.js`：提供不含秘密的部署时配置默认结构。
- `src/core/config/runtime-config.ts`：读取、校验和导出运行时配置。
- `docker/entrypoint.sh`：容器启动时生成实际运行时配置。
- `Dockerfile`：构建一次环境无关镜像，复制 entrypoint 和静态资源。
- `nginx.conf`：提供缓存、CSP、liveness/readiness 和 SPA fallback。
- `.github/workflows/multi-env-ci-cd.yml`：构建、扫描、推送并按 digest 部署同一镜像。

### 3.2 路由与权限

- `src/core/router/registry.ts`：维护动态路由初始化状态、已安装路由和卸载函数。
- `src/core/router/guards.ts`：只处理认证、授权和路由初始化状态机。
- `src/core/router/route-mode.ts`：加载并严格转换路由 manifest，不吞异常。
- `src/features/*/routes.ts`：各 feature 导出自己的路由 manifest。
- `src/app/bootstrap.ts`：组装路由来源、认证状态和权限策略。

目标依赖方向：

```text
app -> core
app -> features
app -> shared
features -> core
features -> shared
core -> shared
shared -> no business feature
```

### 3.3 HTTP 与 API 契约

- `src/core/http/client.ts`：创建可注入认证策略的 Axios 实例。
- `src/core/http/interceptors.ts`：处理可信 origin token、取消、去重、重试和 401 single-flight。
- `src/core/http/endpoint.ts`：结构化 path params、query、body 和 response parser。
- `src/core/http/request.ts`：统一 envelope、业务错误码和错误归一化。
- `src/features/*/api.ts`：只描述领域端点和轻量业务适配，不手写 URL replace。

### 3.4 业务开发黄金路径

- `src/shared/components/pro/ProTable.vue`：泛型数据、仅最新请求生效、错误态和重试。
- `src/shared/components/pro/ProForm.vue`：校验、重置、字段 props、提交状态和服务端字段错误。
- `src/shared/composables/useMutation.ts`：统一 mutation 状态、通知和错误传播。
- `src/features/system/views/UserManageView.vue`：完整 CRUD 参考实现。
- `src/features/auth/permission.ts`：保留纯权限策略。
- `src/features/auth/usePermission.ts`、`src/features/auth/components/AccessControl.vue`：操作级权限能力。

### 3.5 测试与门禁

- `src/core/http/interceptors.test.ts`：HTTP 安全和并发行为。
- `src/core/router/guards.integration.test.ts`：真实 Router、Pinia 和会话生命周期。
- `src/shared/components/pro/ProTable.test.ts`：异步、分页、搜索、竞态和错误态。
- `src/shared/components/pro/ProForm.test.ts`：字段更新、校验和暴露 API。
- `src/features/system/views/UserManageView.test.ts`：CRUD 行为。
- `e2e/core-flow.spec.ts`：认证、RBAC、401 和会话恢复。
- `e2e/system-user.spec.ts`：用户管理黄金路径。

## 4. 阶段与依赖关系

| 阶段 | 目标                     | 前置条件             | 完成标准                                         |
| ---- | ------------------------ | -------------------- | ------------------------------------------------ |

| P3   | 质量门禁与架构治理       | P0-P2 对应能力已存在 | CI 真实执行 coverage、E2E、审计和边界规则        |

## 9. 完整验收标准

### 9.1 安全与发布

- [x] production 缺少 API 配置时构建或启动明确失败，不回退 localhost。
- [x] production 无法启用 MSW。
- [x] 第三方 origin 请求不携带 Authorization。
- [x] CSP 不阻断实际 API、Sentry 和必要连接。
- [x] 构建、扫描、部署和回滚使用同一 image digest。
- [x] workflow 不包含 `eval`，用户输入不进入 shell 源码。
- [x] `pnpm audit --prod --audit-level high` 无未批准 high 漏洞。

### 9.2 认证与路由

- [x] 公开路由必须显式声明，业务路由默认 fail-closed。
- [x] admin logout 后 viewer 登录，不存在 admin/system 残留路由。
- [x] 后端路由失败显示可重试错误，不伪装成 404。
- [x] 未知 component 或非法 route config 被拒绝并上报。
- [ ] 菜单与 Router 使用同一 route manifest。

### 9.3 HTTP 与 API

- [x] 去重 A/B/C 竞态测试通过。
- [x] 调用方 AbortSignal 生效。
- [x] canceled 请求不会自动重试。
- [x] 并发 401 只执行一次 session 失效流程。
- [x] 所有 `:pathParam` 由统一 endpoint builder 解析和编码。
- [x] HTTP 200 的业务失败码不会被当作成功数据。

### 9.4 业务开发体验

- [x] ProTable 支持类型推断、error、retry、stale 和 latest-only。
- [x] ProForm 支持 validate、reset、required、field props 和服务端字段错误。
- [x] 用户管理示例覆盖 CRUD、权限、i18n、loading、success 和 failure。
- [x] 操作权限有统一 composable 和组件。
- [ ] 移动端 375px 不出现关键操作不可达或固定宽度溢出。
- [ ] 主题只使用一个事实源。

### 9.5 可观测性

- [x] bootstrap、Vue global error、ErrorBoundary、unhandled rejection 和 HTTP operation error 有统一捕获链。
- [x] 用户可获得错误反馈和 event ID。
- [x] 不再使用空表、旧数据、0% 或"正常"掩盖请求失败。
- [x] Web Vitals 进入实际 collector，而不是只输出 console。

### 9.6 质量门禁

- [ ] CI 执行 lint、format check、typecheck、coverage、API contract、E2E、Storybook、a11y、audit 和 build。
- [ ] coverage 默认统计真实源代码，不使用少量白名单。
