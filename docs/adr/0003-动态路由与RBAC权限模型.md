# ADR-0003: 动态路由与 RBAC 权限模型

## 状态

已采纳（2026-07 修订：feature route manifest、route registry、fail-closed）

## 背景

需要按用户角色动态展示可访问页面，未授权用户不应看到路由。同时需要解决账号切换时旧路由残留、后端路由加载失败静默吞错、权限 fail-open 等安全问题。

## 决策

### 路由分层

- 静态路由仅注册公开页面（login、403、404、500）
- 业务路由按 feature 模块组织在 `src/features/*/routes.ts` 中导出 route manifest
- `app/bootstrap.ts` 组装 feature routes、auth policy 和 router registry
- core 只保留通用路由机制，不维护业务路由列表

### 显式公开模型（Fail-Closed）

- 公开路由必须使用 `meta.public: true` 显式声明
- 未声明公开的业务路由默认要求认证
- 声明 `roles`/`permissions` 时强制执行 `canAccess()` 校验
- roles 是任一匹配（OR），permissions 是全部匹配（AND）

### 动态路由注册表

- `src/core/router/registry.ts` 维护 session-scoped 状态：已安装路由 Map、初始化标记、加载 Promise
- `installDynamicRoute(router, route)` 安装单个路由并注册 remover
- `resetDynamicRoutes(router)` 卸载所有已安装路由并清除状态
- 登出、401 和账号切换时调用 `resetDynamicRoutes()`，新身份在旧路由卸载后再初始化

### 路由 manifest 契约

- 每个 feature 导出自己的路由数组，包含页面 loader、默认 meta、权限和 component key
- `meta.titleKey` 指向 i18n 翻译 key，菜单与 Router 使用同一 manifest
- 后端路由（如有）必须经过严格校验：未知 component、重复 route name、非法 path 或缺失安全元数据时返回错误

### 权限能力

- `usePermission()` composable 提供响应式 `hasRole`/`hasPermission`/`canAccess`
- `AccessControl` 组件支持隐藏内容或展示 disabled fallback
- 操作权限统一使用 `<module>:<resource>:<action>` 命名，禁止散落 `includes()`

## 后果

- 直接访问动态路由 URL 需要 catch-all 重新解析
- 未登录用户看不到 404（被重定向到 login）
- 角色变更需重新登录触发路由重置和重新注入
- admin logout 后 viewer 登录，不存在 admin/system 残留路由
- 后端路由失败显示可重试错误，不伪装成 404
- 新增 feature 只需导出 route manifest 并注册到 dynamic-routes.ts
