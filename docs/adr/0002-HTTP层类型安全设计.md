# ADR-0002: HTTP 层类型安全设计

## 状态

已采纳（2026-07 修订：结构化 endpoint、401 single-flight、响应校验）

## 背景

需要在编译期保证 API 请求/响应的类型正确性，减少运行时类型错误。同时需要解决 token 注入安全、请求并发控制、取消/去重/重试状态机和 401 并发处理等运行时问题。

## 决策

### 类型系统

- 使用 `defineGetEndpoint/definePostEndpoint/definePutEndpoint/defineDeleteEndpoint` 声明端点，携带 phantom type
- `InferEndpointRequest/InferEndpointResponse` 从端点声明推导类型
- `ExtractPathParams<TPath>` 通过模板字面量类型自动提取 `:param` 段

### 结构化调用契约

- `requestEndpoint(endpoint, { pathParams, query, body, config })` 统一分发
- `pathParams` 自动 URL 编码替换，缺失参数在请求发出前抛错
- GET/DELETE 默认使用 `query`，POST/PUT/PATCH 默认使用 `body`；例外需显式声明
- 业务层不再手写 `.replace(':id', id)` 或 `new URLSearchParams()`

### 认证与安全

- 认证头只发送到配置的 API origin 或相对路径，第三方 origin 不携带 Authorization
- 使用独立无认证 client 访问第三方服务

### 并发与状态机

- 请求去重采用 compare-and-delete 策略，A 被 B 取消后 A 的 finally 不删除 B
- 调用方 AbortSignal 与内部去重 signal 组合，内部不得覆盖调用方 signal
- 取消请求（ERR_CANCELED、AbortError、aborted signal）不进入重试
- GET 对 408/429/500/502/503/504 执行指数退避重试；POST/PUT/DELETE 默认不重试

### 401 Single-Flight

- 并发 401 只执行一次 session 失效、动态路由 reset、通知和登录跳转
- handler 类型为 `() => void | Promise<void>`，拦截器保存唯一 in-flight Promise
- `router.replace()` 必须被 return/await，导航失败进入统一 telemetry

### 响应校验

- endpoint 可携带 response parser，运行时校验关键接口响应结构
- HTTP 200 但业务 code 失败必须 reject，不伪装成成功数据

## 后果

- 新增 API 必须先声明 endpoint 再调用
- 类型安全在编译期保证，零运行时开销
- Mock handler 可复用同一类型定义
- `:pathParam` 未解析时请求不会发出，避免 404 静默失败
- 并发 401 不会产生多个登录跳转或未处理 rejection
