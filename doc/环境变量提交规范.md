# 环境变量文件提交规范

## 目的

- 统一团队对环境变量文件的提交策略，降低配置不一致带来的协作成本。
- 在保证多环境配置可见性的同时，避免敏感信息进入仓库。

## 适用场景

- 本规范适用于“配置公开、无敏感信息”的团队协作场景。
- 允许将各环境的公共配置提交到仓库，便于成员直接查看与复用。

## 提交与忽略规则

- 允许提交：
  - `.env`
  - `.env.development`
  - `.env.test`
  - `.env.production`
  - `.env.example`
- 自动忽略：
  - `.env.local`
  - `.env.*.local`

## 配置原则

- 所有可提交的环境变量必须是非敏感配置（例如公开 API 地址、开关类参数）。
- 变量命名统一使用 `VITE_` 前缀，确保 Vite 构建行为一致。
- 各环境文件保持同名键集合，减少“某环境缺键”问题。

## 密钥与敏感信息要求

- 如果后续有密钥、Token、私有 DSN、数据库账号等敏感信息，必须放在：
  - `.env.local`
  - `.env.*.local`
- 禁止将真实密钥写入可提交的 `.env*` 文件。
- 如发生误提交，需立即轮换密钥并清理仓库历史。

## 团队协作建议

- 仓库中保留 `.env.example` 作为最小可运行模板。
- 新增环境变量时，同步更新 `.env.example` 与各环境文件。
- 提交前执行 `pnpm lint` 与 `pnpm typecheck`，确保改动可用且一致。
